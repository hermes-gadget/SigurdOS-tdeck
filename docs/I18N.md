# SigurdOS i18n

SigurdOS uses a small, allocation-free translation table for UI text. Phase 4
ships four languages; Phases B1/B2 added Dutch, Italian and Portuguese (seven
total, toward Wadamesh's 12-locale parity):

| ID | Native name | Preference value |
| --- | --- | ---: |
| `Language::English` | English | 0 |
| `Language::German` | Deutsch | 1 |
| `Language::French` | Français | 2 |
| `Language::Spanish` | Español | 3 |
| `Language::Dutch` | Nederlands | 4 |
| `Language::Italian` | Italiano | 5 |
| `Language::Portuguese` | Português | 6 |

English is the default. The selected value is stored in the additive
`NodePrefs::language` field under the NVS key `lang`. `set_language()` updates
the active lookup immediately after a successful preference write; the Display
picker schedules a screen rebuild on the next LVGL tick. Home and Chat pick up
the new language when they are rebuilt or revisited.

## Using translations

Include `i18n/i18n.h` and use the `TR()` macro with a typed `StringId`:

```cpp
lv_label_set_text(label, TR(ChatSend));
```

For a formatted translation, keep the format string in the table and format
into a bounded buffer:

```cpp
char text[64];
snprintf(text, sizeof(text), TR(ChatDeleteChannelFormat), channel_name);
```

Do not translate protocol data or user data. Mesh conversation IDs (`DM: `),
channel names, packet fields, and message contents must remain unchanged.
For bounded translated UI text, use `i18n::copy_truncated()`. It delegates to
`src/utils/utf8_util.h` and never splits an accented UTF-8 code point.

## Adding a language

1. Add a value to `Language` before `Language::Count` and update
   `language_count` users as needed.
2. Add the native language name to `kLanguageNames` and a table in
   `src/i18n/i18n.cpp` with exactly one entry for every `StringId`.
3. Keep the English table complete. A `nullptr` or empty entry in a new table
   intentionally falls back to English, which allows incremental translation.
4. Add lookup and persistence coverage in `test/test_i18n/`.
5. Add the language to the picker in
   `src/ui/screens/screen_settings_display.cpp` if it should be user-selectable.

Use the existing `StringId` rather than English source strings as lookup keys;
this keeps typos and format-string changes visible at compile time. When a
translation is intentionally unavailable, the framework returns the English
entry. An invalid ID returns `[missing translation]` so missing UI text is
visible during development instead of silently becoming blank.

## Font audit

No new font data was required for EN/DE/FR/ES. The existing wrappers for
Montserrat 10/12/14/16/24 use this fallback chain:

```text
Montserrat → latin_ext → keyboard_layout → emoji
```

`src/fonts/latin_ext_font.c` is generated with U+00C0–U+017F plus the euro
sign, covering the Phase 4 accented Latin set (`é`, `à`, `ü`, `ß`, and the
other Latin-1/Extended-A characters). The keyboard-layout fallback remains the
existing DejaVu Sans Greek/Cyrillic/Arabic coverage; it was not replaced or
regenerated. The i18n tables therefore add string bytes only and do not add
PSRAM font allocations.
